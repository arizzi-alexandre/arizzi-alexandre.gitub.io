### Elastic IP 

It's a static public IP for our instances. It contains static because we can map it to different instances if one is failing.
We can have 5 static IP.

>  **⚠️ Note:** 
> It's not recommended to use elastic IP and instead is better to use either DNS either loadbalancer.


### Placement groups
Used to determine where your instances will be placed physically. Severals options exist
1. Cluster: High performance, low latency between instance, in one AZ. If the rack shuts down, all the instances laso
2. Spread: Multiple AZ, different material. We use it for instance that we want always UP. Up to 7 instances
3. **Partion** : Partition 1 : [Rack A] [Rack B]      ← instances I1, I2, I3   
Partition 2 : [Rack C] [Rack D]      ← instances I4, I5, I6  
Partition 3 : [Rack E]               ← instances I7, I8
Used for big data.
4. Precision time. Instance placed on hardware directly with time access. 


### Elastic network insterfaces(ENI)
- Network interface, Bounded by AZ. One AZ for one ENI, can assign ENI to instances only if in the same AZ
One use case is failover, if one instance fail, i can detach it and reatach to a new instance.


### EC2 hibernate
The RAM is preserved and written to an encrypted EBS volume.
Usefull if you want to save the RAM, or that you have services that are long to initialize.

>  **⚠️ Note:** 
> EBS volume is connect over the network to the instance and is persistent storage.
